Прежняя условная линия заменена отдельными FI, BI и GND между XIAO и носителем TA6586. Это предложение монтажа в начальном положении электроники 0 / камеры +3 мм. Проводов, установленного жгута и испытания электрических уровней пока нет.

| Сигнал | XIAO | Носитель TA6586 | Длина осевой трассы, мм |
| --- | --- | --- | ---: |
| FI, оранжевый | D0 / GPIO1 | H1 / CMD_FI → R1 → U1.2 | 77,764 |
| BI, синий | D1 / GPIO2 | H2 / CMD_BI → R2 → U1.1 | 81,604 |
| GND, тёмный | GND | H3 / DRIVE_GND | 66,370 |

На носителе уже есть последовательные резисторы и подтяжки; отдельный второй комплект не добавлен. H1…H3 подходят сверху к площадкам с отверстиями. FI/BI обозначают входы моста; фактическое направление движения ещё зависит от подключения мотора. H3 — опорная земля управления, не провод для возврата тока мотора или серво. Итоговая силовая общая точка/защита/USB ещё не квалифицированы; этот жгут сам по себе не задаёт соединения с сырыми выводами LW.

Диаметр каждого изолированного провода в модели предложен **0,8 мм**. Конкретные провод/сечение/изоляция, радиусы изгиба и запас длины не выбраны. Числа в таблице — длины полилиний CAD, **не размеры для нарезки**. Углы в модели показывают направление трассы, а не допустимость острого изгиба реального провода. Прямые паяные хвосты пока без выбранного разъёмного соединения; крепление жгута и разгрузка пайки открыты.

## Как определены выводы XIAO

Назначения D0/GPIO1, D1/GPIO2 и GND сверены по [официальной схеме выводов Seeed](https://files.seeedstudio.com/wiki/SeeedStudio-XIAO-ESP32S3/img/XIAO_ESP32-S3_front_pinout.png), `pins_arduino.h` установленного Arduino ESP32 2.0.17 и текущему `RC_CAR_ESP32/board/xiao_sense.h`. Адаптер PWM использует этот профиль, но не включён в основной программе.

Координаты взяты из [PCB-архива, на который ссылается Seeed](https://files.seeedstudio.com/wiki/SeeedStudio-XIAO-ESP32S3/new-res/202003751_XIAO%20ESP32S3_v1.4_SCH%26PCB_260226.zip). **В URL указана 1.4, внутри — XIAO ESP32S3 V1.5 / Sense1.5.** Использованы металлизированные площадки U9.1, U9.2 и U9.13 диаметром 1,4 мм. Сам архив сохранён только в локальном build, в репозитории — извлечённые координаты и хеши.

Проекция в прежний STEP2023 выровнена по центру платы; направления дополнительно сверены по USB и U.FL. Получается D0/D1 внизу, GND вверху при нынешней установке камеры. Совпадение ориентиров не доказывает одинаковую ревизию платы или всех компонентов. Перед пайкой сверить фактически полученную XIAO с её маркировкой; текущий STEP не содержит доказательства распиновки купленного экземпляра.

| Площадка | X, мм | Y, мм | Z, мм |
| --- | ---: | ---: | ---: |
| Центр D0 | 30,96583 | 83,25 | 23,17 |
| Центр D1 | 28,42583 | 83,25 | 23,27 |
| Центр GND | 28,42583 | 83,25 | 38,51 |

Точка подхода к GND смещена на 0,25 мм внутрь площадки по Z, чтобы оставить зазор до прижима XIAO. Это предложение места пайки, не измерение реального шва.

## Что проверено и что осталось

Маршруты проходят над драйвером сбоку от конденсатора. FI/BI поднимаются в промежутке между USB XIAO и выступающей частью расширения, общий участок идёт на Z=37,3 мм. Исходный проход под платой был отклонён из-за основания/USB; прямой короткий провод D0→H1 пересекает детали и обнаруживается проверкой.

Проверены три объёмные трассы, их попарные пересечения, детали новой платы/держателя, 103 объёма компонентов XIAO, новый антенный кабель, резерв сервисного USB и полость условного кузова. Пересечений не найдено. Для контакта проводов с плоским макетом PCB XIAO исключены только три локальных окна 1,6×1×1,6 мм в объёме37; остальные компоненты/держатель не исключались. Отверстия носителя проверяются по настоящей геометрии PCB, без исключения её объёма.

Не проверены остальные силовые/серво-провода, температурное влияние драйвера, помехи, натяжение, паяные соединения, допуски и обслуживание с подключённым жгутом. Ранее проверенное снятие PCB требовало освобождения проводов; этот результат не переносится на новый жгут. Все другие положения площадок, настоящий кузов и полученная камера остаются открыты.

Воспроизведение: распаковать зафиксированный архив Seeed в `build/xiao-control-harness/vendor`, затем Python из KiCad10.0.6 запускает `tools/extract_xiao_control_pads.py`; далее `uv run --with-requirements tools/cad-candidate-requirements.txt python tools/build_control_harness.py`. Генератор сверяет цепи H1…H3, проверяет геометрию и записывает хеши. Общая сцена наследует модели и лицензии из [NOTICE компоновки 0.5](../packaging-v05/NOTICE.md).
