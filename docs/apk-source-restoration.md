# Восстановление собираемого приложения

25 октября 2026. Ветка `update`, исходный материал — [APK от 26 сентября](../recovery/apk-2026-09-26/README.md). Сетевой код вручную восстановлен на Kotlin по извлечённому байткоду; это реконструкция, а не возвращённая история Git или точный текст потерянных исходников.

В рабочий проект добавлены UDP-кодек, состояние сессии, сокет-клиент, ограниченная HTTP-проверка `/status` и выбор транспорта. Поиск отправляет запросы discovery v1/v2 и предпочитает новый ответ одного ID/адреса. Экран передаёт выбранные ID/порт/транспорт, привязывает UDP к WiFi и сохраняет STOP, сброс ввода при уходе в фон и независимый жизненный цикл видео. Ручной адрес тоже проходит HTTP/ID-проверку; старого автоматического обхода нет.

Сохранены 32-байтовый пакет, порт3334, интервалы OPEN100/ARM50/DRIVE20мс, HELLO4000мс и свежесть ACK200мс. ACK подтверждает конкретный отправленный пакет и его оси; свежесть считается от времени отправки, повторный ответ её не продлевает. Физические выходы XIAO остаются отключёнными.

## Проверки

- Исходные версии инструментов: JDK17.0.20.1, Gradle7.5, Kotlin1.8.10, AGP7.4.0. Собраны приложение и instrumentation APK. Обновление зависимостей продукта не понадобилось; JSON добавлен только как реализация Android JSONObject для JVM-тестов.
- Полный JVM-прогон: 59 тестов, 0 ошибок, 1 пропущенный условный firmware-fleet тест без native bridge. Он проверен отдельным историческим стендом и не считается текущим результатом.
- До реализации наблюдались падения новых тестов из-за отсутствующих классов и discovery v2. Проверены формат/отбраковка пакетов, неправильные ID/attempt/token/оси, повторы, дедлайны до обработки receive, время первоначальной ARM, STOP, ошибочный/слишком большой/redirect HTTP-ответ и отмена во время блокирующего probe.
- Сам Kotlin UDP-клиент на ПК общался с исходной прошивкой XIAO 10с:453ACK, максимальный RTT97мс; вперёд/назад и STOP подтверждены HTTP. Это одна сессия через ПК и LAN, не измерение телефонного RF или физического движения.
- Полная цепочка `CarControlConnection → HTTP probe → UDP` на ПК отдельно прошла 30с, две команды направления и STOP с нулевым финальным HTTP-состоянием. Эти два стенда компилировались отдельным Kotlin2.4 CLI; сам Android-проект собран штатным Kotlin1.8.10. [Отчёты и хеши](evidence/apk-source-restoration-2026-10-25/summary.json).
- Android-проверка собирается: обновлены семь существующих loopback UI-сценариев и добавлен UDP-сценарий выбора без ARM, движения и STOP при удерживаемом вводе. Отдельный 30с UDP-стенд требует явного `udpBenchHost` и отказывается работать с включёнными физическими выходами. Выполнение на Samsung ещё ожидается.
- Независимое ревью не нашло существенных ошибок управления. Исправлена найденная ошибка выбора instrumentation-пакета: runner теперь выводит его из согласованных app/test build metadata, чтобы не проверить старое приложение вместо новой сборки. Два Python-теста соответствия пакетов проходят. Проверка эмулятором не состоялась: отсутствует аппаратное ускорение, программный запуск завершился ошибкой выделения памяти; собственные процессы остановлены.

## Установка с сохранением старого приложения

SHA256 сертификата установленного APK: `7b746356e115bc7a36ce83991ed73d4bfc069badbb0ea4e333092ecc5d03f76a`.
SHA256 текущего debug-сертификата: `1ba0e7e4716889668a9739ec93912bd955556910be496b08e095bec01db094a6`.
Ключ подписи из APK не восстанавливается. Поэтому тестовая сборка с `-PrecoveryInstall=true` получает пакет `vea.raceremote.recovery`; исходные `vea.raceremote`, test APK и их данные сохраняются. Обычная сборка оставляет исходное имя пакета.

```powershell
$env:JAVA_HOME='D:/RaceRemote-build-checks/tooling/jdk-17.0.20.1+1'
$env:ANDROID_HOME='C:/Users/fetel/AppData/Local/Android/Sdk'
./gradlew.bat --no-daemon -PrecoveryInstall=true :app:testDebugUnitTest :app:assembleDebug :app:assembleDebugAndroidTest
uv run --no-project python tools/run_video_android_smoke.py --serial RF8M811X8FK --adb C:/Users/fetel/AppData/Local/Android/Sdk/platform-tools/adb.exe
```

Сборка APK не доказывает полную эквивалентность утраченному исходнику. Исходники текущей UDP-прошивки C++ всё ещё не найдены; на плату возвращён сохранённый бинарник. Камера отсутствует; мотор, сервопривод, питание/зарядка, калибровка и физическая остановка этим восстановлением не квалифицированы. Печать остаётся отложенной.
