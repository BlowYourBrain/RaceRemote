# Стенд Android ↔ ESP32

2026-09-13. Первый этап — Android; iOS пользователь разрешил пока заменить заглушкой/отложить. iOS-приложение и KMP-модуль ещё не созданы. Идентификатор проекта по прямому указанию пользователя: **vea.raceremote** (applicationId, namespace, Kotlin packages и тесты).

Подтверждены паяльник, мультиметр и 3D-принтер. Подключены:

- Samsung SM-G973F, Android 12, ADB `RF8M811X8FK`.
- ESP32, COM4, CP210x 10C4:EA60; esptool определил ESP32-D0WDQ6 rev 1.0, 4 MB flash, кварц 40 MHz, MAC c8:f0:9e:a6:6d:a0. Название WROOM-32U и micro-USB — со слов пользователя; модель несущей платы ещё не осмотрена. Пользователь подтвердил: внешняя антенна не подключена.

Для повторного измерения устойчивости нужна антенна 2,4 ГГц, 50 Ом, U.FL / I-PEX MHF I. По [Espressif, datasheet v2.7, раздел 9.2](https://www.espressif.com/sites/default/files/documentation/esp32-wroom-32d_esp32-wroom-32u_datasheet_en.pdf) рекомендуемое усиление не выше 2,33 dBi; практически подбираем компактную антенну около 2 dBi. MHF4 — другой разъём. По прямому предложению пользователя отдельно проведён тест без антенны через точку Samsung; результаты ниже. Отсутствие антенны остаётся вероятной причиной нестабильности, но это ещё не доказанная единственная причина.

## Запуск

Прошивка находится в соседнем checkout `C:\Users\Evgeny\orca\RC_CAR_ESP32`, проверенный коммит `940afab`. PlatformIO 6.1.14, espressif32 6.9.0, Arduino ESP32 2.0.17, WebSockets 2.6.1. Сборка `pio run -e esp32-bench`; прошивка `pio run -e esp32-bench -t upload --upload-port COM4`. Закрыть serial monitor перед прошивкой. После запуска serial 115200 печатает READY, имя Wi-Fi и `outputs=disabled`.

До первой прошивки сохранены все 4 MB исходной flash в локальный игнорируемый `RC_CAR_ESP32/artifacts/original-COM4-20260913.bin`. SHA256: `1BDC0AC66B8BF886EAF6503C22232DDF5A0A36311B89590103C4BC407F17D95A`. Это локальная резервная копия, не файл репозитория. Не публиковать: образ может содержать данные старой прошивки.

Android, PowerShell из корня RaceRemote, JDK 17:

```powershell
$env:ANDROID_HOME = 'C:/Users/Evgeny/AppData/Local/Android/Sdk'
$env:ANDROID_SDK_ROOT = $env:ANDROID_HOME
./gradlew.bat :app:testDebugUnitTest :app:assembleDebug :app:connectedDebugAndroidTest --console=plain
```

В настройках телефона выбрать Wi-Fi `RaceRemote-a06da6`, пароль `RaceRemote-01`. Samsung спрашивает о сети без интернета — в испытании выбрано «Только в этот раз». В приложении адрес `192.168.4.1`, затем «Подключить». Газ и руль доступны после ACK, «СТОП» сбрасывает сессию. Для диагностики доступен HTTP `http://192.168.4.1/status`, лог Android с тегом `RaceRemoteControl` и serial контроллера.

Новая debug-сборка установлена на Samsung; прежняя тестовая установка удалена после смены идентификатора. Проверка пакета на телефоне прошла. [Результаты проверки связи и открытые проблемы](control-v1.md#проверка-и-ограничения) отделены от успешной сборки: пока это стенд команд, не ездящая машинка.

## Обратная схема: точка доступа на Samsung

По просьбе пользователя 13 сентября проверена схема Samsung AP → ESP32 STA, устройства рядом, антенна отсутствует. Роутер до этого не тестировался: первая схема была ESP32 AP → Samsung STA.

В прошивку добавлено окружение `esp32-bench-sta`, проверенный коммит `296fd3b`. Обе сборки AP/STA и host-тесты прошли; STA прошита в физическую плату. Скопировать `prototype/secrets.example.h` в игнорируемый `prototype/secrets.h`, указать сеть и пароль, запустить точку 2,4 ГГц WPA2 и прошить `pio run -e esp32-bench-sta -t upload --upload-port COM4`. Адрес ESP32 читать в Serial после DHCP и вводить в приложение. Протокол, тайм-ауты и отключённые GPIO сохранены. Общая папка `.pio` и локальные credentials в Git не включаются.

Точка на Samsung настроена через системный экран: SSID `RaceRemote-Bench`, пароль стенда `RaceRemote-01`, 2,4 ГГц, WPA2. Прямой `cmd wifi start-softap` отвергнут Android из-за MAINLINE_NETWORK_STACK; обычный экран настроек сработал. Wi-Fi-клиент телефона выключен; после теста точка оставлена включённой, приложение остановлено кнопкой «СТОП».

ESP32 получила `192.168.231.9`, интерфейс точки Samsung — `192.168.231.61/24`; это адреса конкретного запуска, не постоянные настройки. RSSI при подключении −78 dBm. Три ICMP-запроса прошли без потерь, RTT 9,2–120,4 мс; такой короткий ping не доказывает устойчивости.

| Повтор | От HELLO до обнуления, по времени получения Serial на ПК | Первый ARM ACK, по Android | Итог |
| --- | --- | --- | --- |
| 1 | 4,204 с | 14 мс | Тайм-аут; до него обе оси и отпускание отработали |
| 2 | 0,594 с | 13 мс | Тайм-аут; небольшой ненулевой газ затем обнулён |
| 3 | 0,594 с | 10 мс | Тайм-аут |

В повторе 1: газ 62…337 → 0 при seq=26; руль 16…313 → 0 при seq=54. Оба возврата произошли при `active=1 armed=1`, до последующего тайм-аута. Это подтверждает передачу осей и отпускания на физическую ESP32, но не движение мотора. [Сохранённые события Serial](evidence/hotspot-smoke-2026-09-13.json); полные локальные логи — `RC_CAR_ESP32/artifacts/hotspot-smoke.json` и `hotspot-android.log`. При первой ручной попытке сессия длилась около 5 с и также закончилась тайм-аутом.

Вывод: режим станции и маршрут от приложения на самой точке работают; стабильность без антенны не подтверждена. Увеличение порогов 200/250 мс для сокрытия обрывов не выполнялось. Следующий сравнительный тест — тот же стенд с антенной; сборка физического привода остаётся отдельной задачей.
