# Проверка выбранной машинки до ARM

15 сентября 2026. CONTROL-IDENTITY-01 v0.1 — расширение Control v1 для Android и прошивки стенда. Цель: при подключении по результату поиска проверить, что по этому адресу отвечает выбранный chip ID. Это защита от случайной путаницы адресов, **не аутентификация участника сети**.

## Подключение

1. Выбор строки Discovery сохраняет полный 48-битный chip ID вместе с host/port; он виден в настройках подключения. Сам выбор не открывает управление.
2. «Подключить» для выбранной машины открывает WebSocket `/control/identity` и требует её ID. Старый ручной режим продолжает использовать `/control`.
3. На новом пути прошивка резервирует владельца обычным `Control.connect`, отправляет IDENTITY и затем HELLO с тем же токеном. Занятую машину по-прежнему нельзя перехватить; отказ подключения не отправляет IDENTITY/HELLO.
4. Android проверяет полный ID и связь токена IDENTITY с HELLO. Только после этого отправляет нейтральный ARM. Сам IDENTITY не разрешает управление и не продлевает исходный срок ожидания 4000 мс.
5. Неверный/отсутствующий ID, повтор префикса, другой токен или истёкший срок закрывают соединение без ARM. Автоматического перехода в ручной режим нет. ACK 200 мс и контроллерный watchdog 250 мс не меняются.

Реальное редактирование поля адреса снимает выбор ID и возвращает порт 1337. На экране появляется «Ручной адрес · ID не проверяется». Это сохраняет ручной стендовый режим; простое несовпадение ID не снимает проверку. Изменение выбранного ID также закрывает прежнюю видеосессию, даже если host/port совпали. Принадлежность самой камеры этим расширением не проверяется.

## IDENTITY: бинарный префикс

Отдельное сообщение WebSocket ровно 16 байт. Не является пакетом движения; нормированные оси в нём отсутствуют. Многобайтовые числа little-endian.

| Байты | Значение |
| --- | --- |
| 0–1 | ASCII `RC` |
| 2 | 1 |
| 3 | 130 (`0x82`) |
| 4–7 | uint32 ненулевой токен последующего HELLO |
| 8–13 | 48-битный ненулевой `ESP.getEfuseMac()`, тот же порядок и значение, что в Discovery |
| 14–15 | нулевой резерв |

Общий вектор C++/Kotlin: `5243018278563412c8f09ea66da00000`, token `0x12345678`, chip ID `0xa06da69ef0c8`. ARM/DRIVE/STOP/HELLO/ACK сохраняют прежние форматы.

Путь сопоставляется точно с `/control/identity`, по длине и байтам. В используемой WebSockets 2.6.1 `WStype_CONNECTED` передаёт `cUrl.c_str()` и `cUrl.length()`; это проверено в локальном исходнике библиотеки. Query-суффикс не включает расширение. Префикс и HELLO отправляются после освобождения mutex; если отправка префикса не удалась, сокет закрывается. Сбой доставки не заменяет независимый watchdog.

## Совместимость

- Новый Android с ручным адресом работает по прежнему Control v1.
- Старый клиент на `/control` получает обычный HELLO от новой прошивки.
- Новый Android после выбора через поиск требует расширение. Если старая прошивка отвечает сразу HELLO, клиент сообщает об отсутствии подтверждения ID и не отправляет ARM. Для этого режима плату нужно обновить; текущую WROOM в рамках этой задачи не прошивали.
- Сетевой участник способен подделать и Discovery, и IDENTITY: TLS, секретное сопряжение и защита от активного злоумышленника не добавлены. Подмена физической платы по тому же IP обнаруживается только если она сообщает свой реальный ID.

## Проверки и пределы

Девять новых JVM-тестов проверяют общий вектор, неверные поля, правильную последовательность, чужой ID, старый HELLO, несовпадение токена, повтор префикса и оба срока ожидания. Отдельно проверено, что IDENTITY без HELLO не вызывает ARM. Финальный запуск с подключённым native bridge дал **47 успешных JVM-тестов без пропусков**. Без `RC_CONTROL_BRIDGE` обычный запуск пропускает один интеграционный сценарий. Отдельный fleet runner также прошёл основную проверку и обнаружил намеренно внесённый перехват; он использует прежний ручной путь, а не IDENTITY.

Два новых теста Samsung используют настоящий `CarControlScreen` и клиента, заменяя только источник строки выбора контролируемой кнопкой. Проверяются сохранение ID, путь запроса, успешное подтверждение, отказ чужому ID без ARM/автоматического обхода и явный ручной режим после редактирования адреса. Это проверка реакции экрана на выбор, без нового UDP-поиска по Wi-Fi. Все **семь Android smoke-тестов прошли**. Первоначально ручной тест заменял адрес идентичным текстом, не вызывая изменения поля; теперь он очищает и заново вводит адрес. Условие отказа без ARM не менялось.

Прошивка: общий вектор и точный путь проверены C++; `run_drive_checks.py` включает новый тест. Собраны четыре целевых варианта WROOM AP/STA и XIAO car QVGA/VGA. Проверки интеграции привода и синтаксические пробы опционального пути с тестовой калибровкой прошли; они не загружают прошивку и не подтверждают работу физических выходов. Все штатные варианты сохраняют отключённый аппаратный привод.

[Сохранённые отчёты и хеши](evidence/control-identity-v01/summary.json). Нет проверки нового обмена на реальной ESP32, новых измерений RF/FPV или физической остановки; полные прежние opt-in ELF относятся к старому runtime, а не к этому изменению.
