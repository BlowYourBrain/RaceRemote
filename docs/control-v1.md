# Control v1 — протокол первого стенда

Дата: 2026-09-13. Статус CONTROL-01/STOP-01: реализован для стенда, частично проверен на Samsung и ESP32. Это инженерный выбор для прототипа, не утверждённые пользователем пределы серийной системы. Старый двухбайтовый протокол несовместим с v1.

Участники: Android `vea.raceremote` ↔ `RC_CAR_ESP32/prototype`. По умолчанию ESP32 — точка доступа: SSID `RaceRemote-a06da6`, пароль стенда `RaceRemote-01`, адрес `192.168.4.1`, WebSocket `ws://192.168.4.1:1337/control`. Дополнительная сборка `esp32-bench-sta` подключает ESP32 к внешней точке; адрес назначает DHCP, порт 1337 и формат пакетов сохраняются. Пароль открыто документирован только для стенда; токен сессии не является аутентификацией. Обнаружение реализовано для стенда в Discovery v1 (UDP 3333); защищённое сопряжение и проверка общей сети 4–6 машин ещё открыты.

## Пакет

Одно бинарное сообщение WebSocket, ровно 16 байт, многобайтовые поля little-endian. Фрагментированные сообщения не поддерживаются.

| Смещение | Поле | Формат |
| --- | --- | --- |
| 0–1 | Сигнатура | ASCII `RC` |
| 2 | Версия | uint8, 1 |
| 3 | Тип | ARM=1, DRIVE=2, STOP=3, HELLO=128, ACK=129 |
| 4–7 | Токен сессии | uint32, ненулевой случайный токен контроллера |
| 8–11 | Номер | uint32, счётчик с переходом через 0xffffffff |
| 12–13 | Газ | int16, −1000…1000, 0 — нейтраль |
| 14–15 | Руль | int16, −1000…1000, 0 — центр |

Это нормированные величины, не PWM и не угол. Полярность, тормоз, питание и механические пределы определяются будущими DRIVE-01/STEER-01. Общий тестовый вектор: `524301027856341201efcdab18fce803` = DRIVE, token 0x12345678, seq 0xabcdef01, газ −1000, руль +1000.

## Сессия и отказы

1. Первое соединение резервирует единственного владельца. Контроллер отправляет HELLO с seq=0 и нейтралью. Второе соединение отвергается, не останавливая владельца.
2. Клиент отправляет ARM с тем же токеном, seq=1 и нейтралью. Управление UI включается только после соответствующего ACK.
3. DRIVE содержит полное текущее состояние и следующий последовательный номер. ACK возвращает принятый номер и логические значения; это не измерение работы двигателя.
4. Android проверяет очередь каждые 20 мс (не более 50 команд/с), допускает только одну неподтверждённую команду. Повторной отправки и накопления очереди команд нет. ACK должен поступить раньше 200 мс; ожидание первоначального HELLO ограничено 4 с.
5. Контроллер обнуляет состояние через 250 мс без допустимой команды. Проверка отдельной задачей каждые 5 мс и перед обработкой пакета; это программный срок, физическое торможение ещё не измерено.
6. Неверный пакет владельца, токен, порядок или тип завершают сессию и обнуляют состояние. STOP владельца с правильным токеном принимается независимо от номера. Закрытие сокета также обнуляет состояние.
7. STOP, фон/пауза приложения и ошибка связи сбрасывают ввод клиента. Перед закрытием клиент пытается отправить STOP; доставка при немедленном закрытии не гарантируется, окончательная защита — watchdog контроллера. Переподключение только явной кнопкой с новым HELLO/нейтральным ARM. Отпускание ползунка возвращает соответствующую ось в 0.
8. Камера не участвует в разрешении управления. В прототипе её пока нет.

Android использует Wi-Fi socket factory для локального устройства даже при мобильном интернете, TCP_NODELAY и Wi-Fi low-latency lock на время соединения. Основание для lock: [Android WifiManager](https://developer.android.com/reference/android/net/wifi/WifiManager#WIFI_MODE_FULL_LOW_LATENCY). Получение lock само по себе не доказывает задержку конкретного телефона.

## Проверка и ограничения

13 сентября: 20 JVM-тестов Android прошли (16 прежних + 4 протокола/сессии). C++ host-тесты проверяют кодек, единственного владельца, ARM, диапазоны, повтор/старый токен, STOP, отключение, границу 249/250 мс и переполнение часов/счётчика. Android instrumentation-тест на SM-G973F / Android 12 подтвердил `vea.raceremote`.

На реальном Samsung получены HELLO/ACK от прошитой ESP32. До TCP_NODELAY первый ARM задерживался примерно на 200 мс; после изменения получены первые ACK за 11–17 мс. В коротком последующем фрагменте RTT доходил до 166 мс и затем происходил тайм-аут. Устойчивая сессия ещё НЕ подтверждена. Пользователь сообщил об отсутствии антенны и затем прямо предложил проверить обратную схему с точкой доступа на телефоне. Она подключилась, но тоже давала тайм-ауты. Эти значения не являются p95 или результатом длительного испытания.

Первый тест ползунка руля дал на ESP32 значения 37…436 и возврат логического состояния в 0 при закрытии сессии. Последующий тест через точку Samsung подтвердил обе оси и отпускание без разрыва: газ до 337, руль до 313, затем 0 при `armed=1`. Три повторные сессии длились примерно 4,2 / 0,6 / 0,6 с до обнуления; первые ARM ACK заняли 14 / 13 / 10 мс. Длительный заезд, два владельца на реальных телефонах и физическая остановка ещё требуют проверки. Все GPIO привода выключены на уровне реализации: прошивка их не настраивает. Контроллер питается по USB, мотор, серво и камера не подключены этой прошивкой.

Реализация и воспроизводимый запуск описаны в RaceRemote `docs/control-bench.md`. Каноническая спецификация находится в RaceRemote; в репозитории прошивки должна быть идентичная копия `docs/control-v1.md`.
