# Discovery v1 — поиск машинок

Дата: 2026-09-13. DISCOVERY-01 реализован для стенда Android ↔ ESP32, проверен на одной плате через точку Samsung. Это инженерный выбор прототипа; защищённое сопряжение и работа 4–6 физических машин ещё открыты.

Прошивка `RC_CAR_ESP32` — коммит `e768f14`. SHA256 загруженной STA: `047940ec17d3e0c24441a712581ef11c201ca514f55a6241ce90cb8131a95d85`. Итоговый APK установлен на Samsung, SHA256: `9d7fd8ab0fba17ffbad1256e50f91264875195693229bb4cc4d38c1d8d233b26`; после тестов уточнён только текст подсказки об общей сети, сборка повторена успешно.

## Поведение

«Найти» ищет 3 секунды: UDP-запрос каждые 500 мс на broadcast-адреса доступных локальных IPv4-интерфейсов, порт 3333. Если Android предоставляет Wi-Fi Network, сокет привязан к нему; для точки телефона используется обычная маршрутизация. Поиск не открывает WebSocket и не меняет управление. Во время подключения кнопка недоступна.

Выбор строки с именем, адресом и занятостью заполняет адрес/порт без подключения управления. При изменении адреса/порта [прежнее видео закрывается, URL камеры сбрасывается](car-video-selection.md). Затем требуется отдельное «Подключить» и HELLO/нейтральный ARM Control v1; видео запускается отдельным «Смотреть». Ручной ввод возвращает порт 1337. Ключ строки — полный chip ID и адрес; короткое имя не считается уникальным.

Закрытие диалога, пауза/фон и новый поиск закрывают старый сокет. Ответы старого поиска игнорируются. Максимум 32 результата. Отсутствие ответов не блокирует ручное подключение; изоляция клиентов, VLAN и фильтрация broadcast могут препятствовать поиску.

## Пакеты

Запрос ровно 12 байт, ответ 24; многобайтовые числа little-endian. ESP32 отвечает unicast с порта 3333 на адрес/порт отправителя.

| Смещение | Запрос | Ответ |
| --- | --- | --- |
| 0–2 | ASCII `RRD` | ASCII `RRD` |
| 3 | Версия 1 | Версия 1 |
| 4 | Тип 1 | Тип 2 |
| 5 | Резерв 0 | Резерв 0 |
| 6–7 | Резерв 0 | uint16 WebSocket-порт, сейчас 1337 |
| 8–11 | uint32 случайный nonce, 1…0xffffffff | Тот же nonce |
| 12–19 | — | uint64 `ESP.getEfuseMac()`, младшие 48 бит |
| 20 | — | Версия Control, 1 |
| 21 | — | Занятость 0/1: `control.active`, включая резерв до ARM |
| 22–23 | — | Резерв 0 |

Общие векторы Kotlin/C++: запрос `525244010100000078563412`, ответ `525244010200390578563412c8f09ea66da0000001010000`. nonce `0x12345678`, chip ID `0xa06da69ef0c8`, имя `RaceRemote-a06da6`, занята, порт 1337.

Android проверяет размер, заголовок, резерв, nonce, ненулевой порт, допустимый chip ID, версию Control и занятость. Принимает только локальный IPv4 (private/loopback), порт источника 3333. ESP32 обрабатывает один пакет за итерацию; чтение занятости под mutex не обновляет watchdog и не включает GPIO.

Поиск — подсказка адреса, **не аутентификация**. Nonce отсеивает старые ответы, но не подделку участником сети. Занятость может устареть; владение решается Control v1. После смены DHCP адрес может принадлежать другой плате: текущий HELLO не подтверждает chip ID. URL камеры подставляется по host, но обнаружение камеры и подтверждение её принадлежности машинке не реализованы.

## Проверка 13 сентября

- 27 JVM-тестов прошли: в том числе кодек, неверные ответы, два ID, старый nonce, отмена поиска. UDP-ответчики работают на loopback одного ПК, это не две физические платы.
- 2 Android-теста на SM-G973F / Android 12 прошли: пакет приложения и независимость управления от ошибки видео/остановка при фоне.
- C++ Control/Discovery-тесты прошли. AP/STA прошивки собраны; STA загружена на COM4 с проверкой хеша flash.
- Samsung нашёл реальную WROOM-32U через `RaceRemote-Bench`: `RaceRemote-a06da6`, `192.168.231.9`, «Свободна». [Снимок](evidence/discovery-found.png).
- После выбора приложение показывает «Не подключено». HTTP `/status`: `outputsEnabled:false`, `armed:false`, `throttle:0`, `steering:0`. [Снимок](evidence/discovery-selected.png).
- Serial: `DISCOVERY udp=3333 listening=1`, STA connected, RSSI −76 dBm. Однократный `flash read err, 1000` при открытии/сбросе COM сменился успешной загрузкой; причина не установлена.

Антенна отсутствует. Поиск не доказывает устойчивость управления, FPV или физическую остановку. Мотор/руль K989 разрешены пользователем для будущего стенда, но физические работы отложены по его просьбе; GPIO остаются ненастроенными. Снимки сняты до уточнения пояснения об общей сети внизу основного экрана; поведение поиска не менялось.
