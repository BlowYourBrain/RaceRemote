# Шесть клиентов и настоящая логика владения прошивки

15 сентября 2026. FLEET-CONTROL-01 v0.1 — функциональная проверка взаимодействия на ПК. Это следующий уровень после раздельных Kotlin/C++ тестов, **не испытание шести физических машин или нагрузки Wi-Fi**.

`CarControlClient` и `ControlPacket` из Android-приложения работают на JVM и подключаются к шести локальным WebSocket-серверам. Серверы передают события в один C++ процесс с шестью отдельными экземплярами `rc::Control`. Заголовок `control.h` подключается непосредственно из соседнего репозитория прошивки; его логика и кодек не переписаны на Kotlin. HELLO и ACK кодируются в C++ и разбираются клиентом; ARM/DRIVE/STOP проходят обратный путь.

Адаптер сети и периодический вызов `tick()` являются кодом стенда. ESP32 `main.cpp`, FreeRTOS, GPIO, PWM, камера и механизм аппаратной блокировки выходов здесь не исполняются. Токены стенда детерминированы для проверки смены сессии, а не для аутентификации.

## Результат

Один составной сценарий `FirmwareFleetTest` прошёл все этапы:

| Этап | Наблюдение в C++ и клиенте |
| --- | --- |
| Шесть владельцев | Шесть независимых сессий получили разные газ/руль: 100/−100 … 600/−600 в нормированных единицах |
| Второй водитель для каждой машины | Все шесть попыток отклонены; первоначальные владельцы, токены и команды сохранены |
| Освобождение первой машины | После отключения она принимает новое явное подключение с другим токеном и нулевыми газом/рулём; прежний ввод не повторяется |
| Потеря одной связи | Для третьей машины отброшены команды и скрыто событие закрытия сокета. C++ `tick()` обнуляет её по истечению срока, Android тоже завершает ожидание ACK |
| Остальные пять | После остановки третьей машины номера команд продолжают расти минимум на три, сессии остаются активными и сохраняют свои значения газа |

Числа газ/руль — логические команды, а не мощность мотора. Тайм-ауты 200/250 мс сохранены; сценарий не устанавливает гарантированное время физической остановки. Это короткая функциональная последовательность, не длительный нагрузочный прогон.

Отдельная проверка чувствительности теста: во временной копии `control.h` убран запрет подключения при занятой машине. Тот же сценарий завершился ожидаемой ошибкой `Second connection stole car 0`. Рабочая прошивка не менялась. Корректный результат runner — успешный основной прогон и обнаруженная ошибка в намеренно испорченной копии; ошибка произвольной сборки не считается обнаружением перехвата.

## Воспроизведение и доказательства

Нужны JDK/Android SDK для Gradle и `g++` с C++17 на PATH. Шесть серверов слушают случайные порты loopback. Команда не подключается к USB, не прошивает устройства и не включает привод:

```powershell
$env:ANDROID_HOME = 'C:/Users/Evgeny/AppData/Local/Android/Sdk'
python tools/run_firmware_fleet.py
```

Можно указать `--firmware <путь>` и `--output <путь>`. Runner компилирует адаптер, запускает выделенный JUnit-сценарий, затем проверяет испорченную копию. `--rerun-tasks` исключает использование кэшированного результата с другой C++ программой. Исполняемые файлы и временный заголовок находятся в игнорируемом `build/firmware-fleet-v01`.

[Сохранённые отчёты](evidence/firmware-fleet-v01/summary.json) содержат ревизию прошивки, версию компилятора и SHA-256 `control.h`, исполняемых адаптеров, проверяемых исходников и JUnit-отчётов. Снимки состояния после каждого этапа находятся в `baseline-junit.xml`. При запуске приложение использовало основные исходники из `b48d5ae`; в этой задаче они не изменены. Прошивка также осталась без изменений.

Обычный запуск JVM-тестов **пропускает этот один интеграционный сценарий**, если нет `RC_CONTROL_BRIDGE`. Такое пропускание не является доказательством работы с C++; использовать runner выше. Отдельные 37 JVM- и 5 Samsung UI-тестов описаны в [предыдущем изменении](car-video-selection.md); в этом прогоне выполнен именно новый составной сценарий, без повторного запуска UI.

## Что ещё нужно подтвердить

На настоящих платах остаются владение через ESP32 WebSocket/FreeRTOS, радиосвязь и общий трафик управления/FPV, фактические выходы и остановка. Обнаружение машин и подтверждение chip ID в сессии этим стендом не проверены. Сборка первой машины и дальнейшие испытания всей серии остаются целью; программный стенд не заменяет их.
