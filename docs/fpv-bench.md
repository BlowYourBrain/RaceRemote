# Первый FPV-стенд

Дополнение: [совместная прошивка XIAO](../../RC_CAR_ESP32/docs/combined-bench.md) объединяет управление/обнаружение и камеру в `xiao-car-qvga` / `xiao-car-vga`. Для неё используются Wi-Fi-настройки `prototype`, MJPEG остаётся на HTTP 81, диагностика камеры перенесена на HTTP 82, управление — на прежних портах. Ниже описан исходный раздельный стенд; его можно использовать для сравнения с общей платой. Физической проверки совместной работы пока нет.

Ревизия прошивки **2609953**: все шесть окружений PlatformIO и C++-тесты управления/обнаружения прошли. Совместные QVGA/VGA-образы по 824512 байт, статическая RAM по линкеру 50752 байта; это не измерение свободной памяти во время видео. [Хеши и границы проверки](../../RC_CAR_ESP32/docs/combined-build-evidence.json). Загрузки на плату не было, соответствие протокола `control-v1.md` в двух репозиториях проверено по одинаковому SHA256.

2026-09-13. Статус: подготовлен [Android MJPEG-приёмник 0.1](video-v0.md), проверен синтетическим потоком на Samsung. В соседнем RC_CAR_ESP32 подготовлена и собрана прошивка камеры 0.1 для XIAO ESP32S3 Sense, описанная ниже. Покупка и выбор серийной платы не выполнены; результатов с физической камерой нет. Цель — проверить видео на телефоне до окончательной компоновки машины.

## Состав и подключение

| Деталь | Количество | Статус |
| --- | ---: | --- |
| Плата ESP32-S3 с PSRAM, OV3660 и USB | 1 | Первым компактным кандидатом рассмотреть Seeed XIAO ESP32S3 **Sense** с OV3660; поставщик/ревизия ещё не выбраны |
| USB-кабель с данными под разъём платы | 1 | Для питания и прошивки от ПК; можно использовать имеющийся, наличие у пользователя не установлено |
| ПК и точка доступа Wi-Fi 2,4 ГГц | Общие | Модель/настройки точки доступа неизвестны |
| Android и iPhone | По одному, последовательно | Samsung SM-G973F / Android 12 доступен и проверен с синтетическим видео; iPhone и iOS пока отложены |
| Внешняя камера для записи сцены и экрана телефона | 1 | Для измерения задержки, желательно запись 120/240 FPS; можно одолжить |

```mermaid
flowchart LR
    PC[ПК] -->|USB: питание и прошивка| CAM[Плата с OV3660]
    CAM <-->|Wi-Fi 2,4 ГГц| AP[Домашняя точка доступа]
    AP <-->|Локальный видеопоток| PHONE[Android или iPhone]
```

Первый запуск от USB: отдельные мотор, серво, батарея, зарядник, экран и microSD не нужны. Для платы с поддержкой прошивки по USB внешний программатор не требуется. Существующая WROOM-32U пригодится для последующего теста команд, но не заменяет камеру автоматически.

Нужен комплект Sense с камерой и антенной, а не базовая XIAO или отдельный сенсор. [Пример камеры Seeed](https://wiki.seeedstudio.com/xiao_esp32s3_camera_usage/). Пригодность для 30/60 FPS на телефоне ещё не проверена.

Обнаружена ссылка [AliExpress 1005006988111963](https://aliexpress.ru/item/1005006988111963.html) через поисковую карточку агрегатора. ## Подготовка и критерии измерений

### Подготовленная прошивка XIAO

Исходники: `RC_CAR_ESP32/camera/main.cpp`, локальный коммит **0666e4f**; инструкция и доказательства сборки: `RC_CAR_ESP32/docs/camera-bench.md`, `camera-build-evidence.json`. Окружения PlatformIO **xiao-camera-qvga** и **xiao-camera-vga** используют espressif32 6.9.0 / Arduino ESP32 2.0.17, плату `seeed_xiao_esp32s3` с OPI PSRAM. Распиновка взята из [таблицы Seeed](https://wiki.seeedstudio.com/xiao_esp32s3_camera_usage/#camera-slot-circuit-design-for-expansion-boards), а не из стандартной ESP32-CAM.

Программы подключаются к заданной Wi-Fi-сети и предоставляют `http://<IP>:81/stream` для Android и `http://<IP>:80/status` для диагностики. Проверяются фактический PID OV3660/OV2640 и наличие PSRAM; ошибка не подменяется переходом на другой сенсор/формат. Режимы 320 × 240 / 640 × 480 JPEG, XCLK 20 МГц, JPEG quality 12, два буфера PSRAM, выбор последнего кадра. Это стартовые настройки агента; 30/60 FPS не обещаны. Сервер рассчитан на одного зрителя.

Обе конфигурации собраны без сетевых настроек и с известной публичной тестовой точкой `RaceRemote-Bench`. Полные сетевые образы по 761 248 байт; проверено наличие кода HTTP/захвата в ELF. Прежние сборки управления AP/STA и C++ host-проверки также прошли. **Прошивка на железо не выполнялась**: имеющаяся WROOM-32U не является XIAO и должна сохранять прошивку управления. Подготовка этого стенда не утверждает архитектуру с двумя контроллерами для серии.

Локальные SSID/пароль находятся в игнорируемом `camera/secrets.h`, шаблон — `secrets.example.h`. После получения XIAO сначала проверить сенсор/расширение/антенну, подключить питание по USB, определить её собственный COM-порт, прошить и записать диагностику. Начальная ошибка камеры даст HTTP 503; `cameraReady` означает успешную инициализацию, а не непрерывную проверку исправности. Счётчики отправки и метки захвата не являются измерением задержки до экрана.

### Физические измерения

1. Зафиксировать точную плату, ревизию, сенсор, pinout, SDK/драйвер и исходный пример. Подготовить воспроизводимую сборку с локальными параметрами Wi-Fi, без паролей в Git. Проверить определение сенсора и PSRAM.
2. Предложенные режимы первого сравнения: JPEG/MJPEG 320 × 240 и 640 × 480, один телефон за раз, сначала Android и затем iPhone. Для Android уже есть [приёмник в приложении](video-v0.md); браузер можно использовать для отдельной диагностики.
3. Предложенный прогон — 10 минут на режим, с движением камеры и вечерним освещением. Записать экспозицию/качество, модель телефона/ОС и сеть. Измерять свежие отображённые кадры в секундных окнах, паузы и восстановление. Серверные FPS и частота экрана не доказывают FPS получателя. Требование пользователя остаётся минимум 30, желательно 60 FPS; разрешение и допустимые просадки ещё открыты.
4. Для задержки снять внешней камерой одновременно меняющуюся сцену (например, светодиод) напрямую и её изображение на телефоне. По серии переходов вычислить медиану/p95/максимум и указать временное разрешение записи. Часы несинхронизированных устройств не вычитать. Предельная задержка пока не задана, успешность езды не объявлять по одному FPS.
5. Затем добавить команды с номерами и ответами контроллера, далее мотор/серво и питание от батареи. Проверить FAIL-01: отказ только видео сохраняет управление, потеря команд останавливает привод. Стенд без исполнительных механизмов это не подтверждает.
6. Повторить в будущем Android/iOS-приложении и при нескольких одновременных потоках. Только после результатов выбирать одинаковую конфигурацию серии; перенос на другую плату требует повторной проверки.

Для Waveshare просмотрен `02_CameraWebServer.ino` и `board_config.h` из [примера производителя, ревизия 72af9302030bb6f018d5c21b1225005481e09fda](https://github.com/waveshareteam/ESP32-S3-CAM-OVxxxx/tree/72af9302030bb6f018d5c21b1225005481e09fda/examples/Arduino-v3.2.0/examples/02_CameraWebServer). До камеры инициализируется расширитель I/O; используется JPEG QVGA и один буфер в DRAM, ветка PSRAM закомментирована; при ошибке пробуется RGB565. Пример требует адаптации для измерений, не собран и не прошит. Произвольный стандартный pinout ESP32-CAM вместо конфигурации производителя не использовать.

Ближайший незавершённый результат: получить подходящий модуль с подтверждённым сенсором и проверить подготовленную прошивку на нём. Если будет выбрана Waveshare вместо XIAO, требуется её отдельный pinout/инициализация и повторная сборка. Этот документ фиксирует подготовку эксперимента, а не завершённый физический FPV-стенд.
