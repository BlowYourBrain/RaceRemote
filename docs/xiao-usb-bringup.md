# Первый USB-стенд XIAO

**Позднейшая поправка 25 октября:** это описание загрузки старого стенда. [Восстановление из APK](../recovery/apk-2026-09-26/README.md) показало, что сохранённая до неё flash уже содержит UDP-приложение с новым HTTP-контрактом. Агент не проверил это перед загрузкой a8c25f6, создав несовпадение с установленным APK. Исходное приложение app0 возвращено и проверено с ПК на отключённых выходах; текущий DHCP-адрес192.168.1.122, UDP3334, backend=null. Bootloader/partition table/NVS не восстанавливались. Сентябрьский стенд ниже не является текущей версией на XIAO.

25 октября 2026. Пользователь получил XIAO, SG90 и мотор, подтвердил модуль Waveshare DC5-36-TO-DC3V3-5-M и подключённую антенну XIAO. Камера ещё не получена. Это обновляет сентябрьские сведения об ожидании деталей; физическая сборка машинки и проверка питания не выполнены.

**Последующая проверка в тот же день:** Samsung подключён и проверен агентом; [результаты](xiao-samsung-bench.md). Команды и программная нейтраль работают в отдельных тестах, но связь нестабильна, а обычный экран установленного более нового APK не проходит предварительную проверку старой прошивки. Ручной адрес сам по себе это несовпадение версий не устраняет.

## Что проверено

- Windows: исправный USB Serial/JTAG, COM3, VID303A/PID1001.
- esptool 5.6.0: ESP32-S3 rev0.2, 8 МБ flash, 8 МБ embedded PSRAM; MAC `b8:1f:3f:d9:08:50`.
- Полностью считаны 8 МБ исходной flash. Первая сверка после перезагрузки не совпала; повторное чтение показало изменение только сектора `0xa000` внутри NVS. Вторая копия считана с `--after no-reset` и успешно сверена до запуска исходного приложения. Это не запись прошивки средствами esptool.
- Собран и загружен отдельный `xiao-control-usb`: espressif32 6.9.0, Arduino ESP32 2.0.17, WebSockets 2.6.1, плата `seeed_xiao_esp32s3`. Сборка успешна; образ приложения 737072 байта, статическая RAM по линкеру 46416 байт. Загрузчик, таблица разделов, boot_app0 и приложение прошли встроенную сверку загрузчика esptool.
- В команде компиляции проверены XIAO и USB CDC; отсутствуют `RC_ENABLE_ACTUATORS`, `RC_WITH_CAMERA`, `RC_BENCH_STA`. Компилируется только проектный `prototype/main.cpp`; исходники аппаратных адаптеров мотор/серво исключены.
- После сброса Serial подтвердил `DISCOVERY udp=3333 listening=1` и `READY protocol=1 car=RaceRemote-5008d9 ip=192.168.4.1 ws=1337 backend=null`.

[Машиночитаемая запись](evidence/xiao-usb-2026-10-25/summary.json), [лог запуска](evidence/xiao-usb-2026-10-25/boot-serial.txt), [конфигурация сборки](evidence/xiao-usb-2026-10-25/platformio.ini). Исходные flash-копии и полные журналы находятся только в игнорируемом `build/xiao-usb-2026-10-25/`. Проверенная копия также сохранена вне рабочего checkout: `D:/RaceRemote-device-backups/xiao-b81f3fd90850/original-2026-10-25.bin`; обе копии имеют SHA256 `57668b828e67978ef8d436506564bfdca0d89877223088b77077858fbe9006ef`. Содержимое flash не публикуется.

Для Serial-монитора перед открытием COM3 выставлялись DTR=false и RTS=false, затем применялся USB hard reset. Первая попытка с исходным DTR=true не дала READY; после исправления порядка линий получен приведённый лог. Это не требовало изменения прошивки.

## Версия прошивки

В текущем GitHub-репозитории RC_CAR_ESP32 доступен только начальный коммит `d07267f3ab1e1dba49cf0b39550d60d388bd8828`. Более новые сентябрьские исходники с проверкой ID в этом checkout не найдены. Поэтому для первого стенда использована сохранённая копия runtime `a8c25f61192f787efa5a352b331ae0a35ff93199` из `D:/RaceRemote-build-checks/actuator-link-wr66dxap`: SHA256 всех 19 файлов исходников совпали с её `report.json`. Её старый platformio.ini и старые образы содержат синтетическую калибровку DO-NOT-FLASH; они не использовались для загрузки. Новая отдельная конфигурация не включает аппаратные выходы и не меняет исходники.

Временный стенд поддерживает прежний `/control`, но не более новый обмен IDENTITY. Android не изменялся. В исходниках текущего checkout ручной адрес сохраняет прежний протокол. Однако последующая проверка обнаружила на телефоне APK от 26 сентября с другой предварительной проверкой машинки: его экран завершает подключение JSONException. Для обычного экрана и выбора через поиск сначала нужна согласованная версия прошивки и приложения.

## Состояние после проверки телефона

Агент подключил Samsung к `RaceRemote-5008d9`, принял системный выбор оставаться в сети без интернета, прочитал HTTP `/status`, выполнил тесты старого протокола и проверку экрана. Сравнение с точкой Samsung выполнено, затем исходный AP-образ восстановлен. Телефон оставлен на сети XIAO, тестовая точка Samsung выключена, приложение остановлено. Последний HTTP cleanup успешного теста watchdog подтвердил `outputsEnabled:false`, `armed:false`, `actuatorMode:"disabled"`, `backend:"null"` и нулевой план. [Журналы и ограничения](xiao-samsung-bench.md).

Это не подтверждает устойчивую связь или физическую остановку двигателя. Питание Waveshare, серво, мост TA6586, камера, зарядка и печать остаются отдельными этапами. При доступном ADB пользователь просит выполнять проверки телефона самостоятельно, а не передавать ему ручные шаги.
