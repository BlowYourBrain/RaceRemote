# Контракт, извлечённый из Android APK

25 октября 2026. Источник — Java-представления UdpControlPacket, UdpControlSession, UdpControlClient, DiscoveryPacket, ControlEndpointProbe и CarControlConnection в этом пакете. Описана сторона клиента; внутренние проверки C++ сервера из APK не восстанавливаются.

## Предварительная проверка

GET `/status` с HTTP-порта по умолчанию80. HTTP200; protocol=1; acceptingControl=true. Обязательны controlTransport, controlPort, chipId. chipId разбирается как шестнадцатеричная строка. Проба не следует redirect, ограничивает connect/read двумя секундами, весь вызов тремя; тело8193байта и больше отвергается.

CarControlConnection проверяет ID в1…2^48−1, порт1…65535 и совпадение с выбранными discovery-данными, если они есть. Поддерживаются `udp-v1` с портом строго3334 и `websocket-v1` с проверкой ID через существующий клиент. Неизвестный транспорт не вызывает автоматического перехода на старый протокол.

## UDP3334

Ровно32байта, многобайтовые поля little-endian:

| Смещение | Размер | Поле |
| --- | --- | --- |
| 0 | 3 | 0x52 0x55 0x01: RU и версия1 |
| 3 | 1 | kind: OPEN0, ARM1, DRIVE2, STOP3, HELLO128, ACK129 |
| 4 | 4 | attempt: ненулевой uint32, случайный на подключение |
| 8 | 4 | token: uint32, назначается HELLO |
| 12 | 4 | sequence: uint32 |
| 16 | 2 | throttle: int16, −1000…1000 |
| 18 | 2 | steering: int16, −1000…1000 |
| 20 | 4 | basis: uint32 |
| 24 | 8 | chipId: uint64, допустимы1…2^48−1 |

Кодек проверяет длину, заголовок, ненулевой attempt, ID и диапазоны осей. Допустимость kind/token/sequence для текущей фазы проверяет сессия. Клиент использует подключённый DatagramSocket на адрес машины:3334, тайм-аут приёма5мс, буфер256байт; перед connect предусмотрен bindSocket, которым приложение может привязать сокет к сети Wi-Fi.

## Сессия клиента

- OPEN повторяется не чаще100мс. Исходный срок ожидания HELLO —4000мс; проверяется и перед обработкой входящего пакета.
- HELLO должен совпадать по chipId/attempt, иметь basis0, ненулевой token, sequence0 и нулевые оси. После него начинается ARMING.
- ARM использует sequence1, нулевые оси/basis; повтор не чаще50мс. Срок200мс считается от первой отправки ARM либо от HELLO, если отправки ещё не было; повтор его не продлевает.
- После ARM ACK начинается ACTIVE. Новое состояние передаётся не чаще20мс без ожидания отдельного ACK на каждый DRIVE. sequence увеличивается с uint32-wrap, basis равен последнему принятому номеру ACK.
- Для ожидаемых ACK хранится кольцо из64 отправок. Принимаются только ACK с совпавшими ID/attempt/token, basis0, совпавшим номером ожидаемой отправки и осями. Номер должен двигаться вперёд в unsigned half-range; возраст отправки строго меньше200мс.
- Свежесть подтверждения отсчитывается от времени отправки подтверждённой команды, а не от времени получения ACK. При возрасте200мс сессия закрывается. Повторные, старые и неподходящие ответы не должны её продлевать.
- stop закрывает сессию, обнуляет ввод/подтверждённые оси и очищает кольцо. Если token уже получен, next выдаёт один STOP с текущим sequence, нулевыми осями/basis; после этого возвращает null. Это не гарантия доставки STOP, физическую остановку обеспечивает проверяемая сторона машины.

Эти правила извлечены из клиента; не следует подменять ими неизвестные проверки сервера, особенно смысл basis при приёме DRIVE. Реконструировать всю C++-реализацию по одному формату нельзя.

## Discovery UDP3333

Запрос12байт: RRD, версия1или2, kind1, reserved0, затем нулевые служебные поля и nonce uint32 по смещению8. Ответ24байта: RRD, версия1или2, kind2, reserved0; порт uint16 по6, nonce uint32 по8, chipId uint64 по12. Байт20 должен быть1; byte21 — busy0/1; byte23 —0.

Версия1 требует byte22=0 и означает websocket-v1. Версия2 различает byte22=1 для websocket-v1 и2 для udp-v1. UDP-порт должен быть3334. Проверяются nonce, непустой ID и порт. Это расширение старого discovery, которое отсутствовало в доступном сентябрьском checkout.

## Границы доказательства

Оригинальная UDP-прошивка из сохранённой flash успешно ответила на совместимый HTTP и короткий обмен с ПК с отключёнными физическими выходами. Полное дифференциальное исполнение Java/DEX, долгий прогон и повторный Samsung-тест здесь не выполнены. Типы, таймеры и обработка ошибок должны быть сохранены при последующем переносе в компилируемый Kotlin и проверены тестами; текущие Java-представления сами по себе таким переносом не являются.
